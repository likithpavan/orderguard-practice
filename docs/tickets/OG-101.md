# OG-101: Reject quantities above 1,000 before accepting an order

**Type:** Bug  
**Component:** Order entry / backend validation  
**Practice priority:** High  
**Starting status:** To Do

## Problem

The starter accepts AAPL BUY or SELL with quantity 1001 or 5000. Those orders
enter the accepted ledger. For this exercise, no order may exceed 1000 shares.

## Acceptance criteria

1. BUY and SELL accept whole integer quantities **1 through 1000 inclusive**.
2. Reject quantities above 1000, zero, negatives, fractions, missing values,
   nonnumeric values, and numbers too large to parse safely.
3. Invalid requests return an error: API HTTP 400 and a readable quantity message.
4. Invalid requests add **zero accepted orders**. Existing accepted records remain.
5. Enforce the rule in the backend before accepted-order persistence; direct API
   calls must satisfy the same rule as requests from the screen.
6. Keep existing symbol and BUY/SELL checks working.
7. Complete tests pass without excluding the upper-limit checks.

## Reproduction

Start `starter/OG-101`, run the app, submit AAPL BUY quantity 1001, and inspect
the accepted ledger. Repeat with SELL. Current result: HTTP 201 and a new
accepted order. Required result: HTTP 400 and no increase in accepted count.

## First test example

| Test item | Value |
|---|---|
| Starting accepted orders | 0 |
| Symbol | AAPL |
| Action | BUY |
| Quantity | 1001 |
| Expected decision | Order not accepted; quantity error |
| Expected accepted orders after request | 0 |

Repeat with an existing accepted order: start with count 1, submit invalid
quantity 1001, expect count **1**. “Zero stored” means zero new records.
